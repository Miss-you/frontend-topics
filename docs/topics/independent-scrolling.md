# 独立滚动

## 问题与复现

页面左侧显示日期，右侧是长正文。左侧使用吸顶定位后，看起来像独立区域；鼠标放在日期处滚轮下滑，实际却仍在滚动整页。用只有一个日期、首批日期未填满区域、长日期列表三组数据分别复现。

## 原因

吸顶决定元素相对视口的位置，不能单独建立一个有可用滚动距离的列表。滚动范围还取决于容器尺寸、内容高度与溢出处理。列表没有高度边界，或内容尚不足以溢出时，都可能没有用户预期的局部滚动。

## 交互契约

- 鼠标位于日期滚动区时只浏览日期，滚动本身不选择日期。
- 日期区到达边界时不带动正文；右侧阅读不改变左侧已浏览位置。
- 日期区避开实际顶部导航，标题与低频说明放在滚动区外。
- 初始历史不足以填满区域时只补到可滚动或已无更多数据；失败后显示手动重试，不自动循环重试。
- 窗口尺寸变化只更新布局，不作为读取更多历史的意图。
- 追加历史或恢复同范围失败状态时，保留仍有效日期链接的 DOM 节点与键盘焦点。

## 实现边界与建议

日期组件负责滚动和历史加载状态；消费者提供分页读取回调、日期标签与选择后的正文处理。桌面采用独立滚动，手机可采用横向日期导航和普通纵向阅读。这是当前阅读布局的选择，不适用于所有列表。

在滚动过程中改变列表可视高度，可能使已有 `scrollTop` 被限制到新的范围，造成内容跳动。当前策略让正常阅读时的日期视口保持稳定，在初始化或尺寸变化时重新测量。极低视口、软键盘和复杂嵌套布局需要单独验证。

## 验收与关联

用真实滚轮验证列表顶部、列表底部和正文三处；对比两侧滚动位置，并确认当前日期未改变。补充短列表、历史失败、重复加载与 resize 场景；聚焦已有链接后追加历史，单独断言焦点仍在该链接。具体可执行证据见仓库 [测试目录](../../tests/) 和消费者的集成测试。
