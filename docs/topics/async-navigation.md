# 异步导航状态

## 问题与复现

让刷新请求延迟，期间选择另一日期，再释放较早的响应。可能出现正文被旧内容覆盖，或正文正确但历史按钮一直禁用。另一组复现是连续刷新两次，后一次失败，较早响应最后返回。

## 原因

已成功加载的数据、正在请求的状态与当前用户选择具有不同生命周期。通过清空已提交游标来表达“正在刷新”，会丢失失败后的恢复依据。仅用一个计数器控制整页，也可能让正文更新失效时连带跳过仍需恢复的日期导航。

## 交互契约

- 刷新不销毁最后成功提交的导航状态；失败后可继续使用同一筛选范围的真实历史游标。
- 历史游标绑定其筛选范围，不能把旧作者游标用于新作者。
- 旧响应不能接管更新后的日期、作者或分页状态。
- 正文响应与导航响应按各自范围判定是否仍有效；正文已变化不代表当前筛选的导航恢复也应被跳过。
- 同一历史窗口只保留一次有效加载；失效响应不得再次追加旧数据。

## 解决与边界

使用独立的加载状态暂停操作，保留已提交的数据和游标。每轮导航更新携带可失效的标识；组件提交结果前核对标识与筛选范围。消费者仍需为自己的正文请求、URL 与历史恢复提供相应保护。

请求取消可以减少无用工作，但不能替代结果提交前的有效性检查：读取回调可能不支持取消，较早工作也可能已经完成。这里讨论只读导航；写入、支付或持久化事务需要另外的协议。

## 验收与关联

用可控制释放顺序的假接口，分别验证：刷新中切日期、切作者时旧历史返回、刷新失败后继续加载、连续刷新最后一次失败。断言正文、当前选择、历史按钮和游标后续读取，而不只断言一个标题。
