# 2026-11-09：本地文本对比工具与全站导航验收

## 目标与范围

在一个静态内容站的工具栏目增加浏览器本地文本对比器，支持中英文、明暗主题及手机布局；随后统一多个布局的导航，并验收正式发布的关键路径。最后将可复用机制归档。

公开材料只保留匿名实践与虚构输入，不复制消费者域名、目录、页面原文或生产截图。本仓库此次仅更新知识文档，`daily-ui` 的组件接口、版本及同步产物不变；文本对比器与导航实现仍由消费者维护。

## 问题、原因与改进

最初「纯前端、安全」不足以指导实现。将它拆成文本如何渲染、允许加载哪些脚本、是否持久化、任务如何停止之后，才有可以失败的测试。工具独立布局保留了较小的执行范围，共享导航则复用最小的外观与路由生成逻辑。机制见 [浏览器本地文本工具](../topics/local-text-tools.md)。

导航外观一致后，正式验收仍发现隐藏耦合：图表的主题监听器刷新整个页面，甚至影响没有图表的工具页。修复采用原地重绘与串行合并，而非给每个工具添加自动保存。后者会改变原有隐私约定，也没有消除刷新原因。详见 [共享导航与主题](../topics/shared-navigation.md)。

这次还区分了三个容易混淆的事实：发布产物链接存在、浏览器实际到达页面、输入与异步状态在操作后仍正确。静态全量扫描和少量真实交互分别提供证据，不能合并成「所有页面、所有设备已通过」。触控模拟里的鼠标拖动出现误触，也如实保留为证据缺口。

## 规则复盘

| 候选规则                         | 本次依据                       | 决定           | 适用范围或退出条件                       |
| -------------------------------- | ------------------------------ | -------------- | ---------------------------------------- |
| 主题切换不得刷新整个工具页       | 输入重置的正式复现与回归测试   | 保留消费者契约 | 产品若明确需要重载，先定义状态与用户体验 |
| 同一导航只维护一个模板来源       | 多布局共享资源与产物核对       | 上下文建议     | 不要求业务差异大的界面强行共用整页       |
| 工具需要自动保存以防状态丢失     | 状态丢失来自无关图表刷新       | 不采纳         | 草稿能力应由新的产品需求决定             |
| CSP 或 Worker 能证明工具绝对安全 | 两者各自仅约束部分风险         | 不采纳         | 使用可检验的数据流与资源预算描述         |
| 手机截图等于触控验收             | 模拟中出现误触且缺少可靠 swipe | 不采纳         | 必须获得对应输入方式的证据               |

这些结论归入专题与 FAQ，没有给消费者新增长审批流程，也没有把单次案例包装为通用组件发布。
