## 本次发现与原因

1. **已有日期被整体重建，键盘焦点丢失。** 滚动位置未变，原先仅检查 scrollTop 的测试会遗漏。新增用例先复现焦点从链接变成 BODY，再按稳定日期 key 保留节点，历史追加及同范围刷新失败均保持焦点。
2. **旧响应可能被取消，也可能无法取消。** 消费者旧测试等待一个已取消请求的响应，会错误超时。消费者验证请求生命周期结束且旧内容未混入，共享契约另行验证忽略 abort 的旧 loader 也无法发布结果。
3. **交互措辞必须对应事件。** “移出取消”容易把鼠标移出和点击外部混淆。契约改为 Esc、点击组件外部或焦点离开整个组件，保留输入到清除按钮的内部焦点移动。
4. **证据分层不同。** 本地清单通过不代表与来源一致，来源一致不代表公开页面更新；完整工作区通过也不能代替已提交文件的独立安装验收。它们应分别记录和检验。

具体机制与可执行入口见 [FAQ](../topics/faq.md)、[验收专题](../topics/verification.md) 与 [同步升级](../topics/vendor-updates.md)。

## 规则复盘

保留为硬约束的是明确的所有权与交互承诺：生成副本通过来源更新、摘要漂移必须可见、业务回调不进入通用组件、草稿不发业务请求、旧结果不能覆盖新筛选、历史追加保留焦点。消费者规范只保存这些约束及专题链接，没有新增第二套重复指令文件。

候选规模阈值、移动排版、是否转为包管理，继续是有条件的建议。每次新增案例优先更新原专题、FAQ 与测试；只有新机制才增加专题。失去适用条件的建议可以删除或降级。
